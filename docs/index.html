なぜ差が出るのか

5つの言語は、ソースコードを機械語にするタイミングと、メモリを回収するしくみが異なります。

C++

事前コンパイル（AOT）・GC なし

g++ が実行前にソースコードを機械語へ変換し、時間をかけて最適化します。メモリをいつ解放するかはプログラムが決めるので、実行中に GC（使わなくなったメモリを自動で回収する処理）は動きません。

Rust

事前コンパイル（AOT）・GC なし

rustc が LLVM を使って実行前に機械語へ変換します。所有権という規則によって、メモリを解放する位置をコンパイラが決めます。C++ と同じく実行中の GC がなく、10種類の多くの問題で C++ と Rust が1位と2位を占めます。

Go

事前コンパイル（AOT）・GC あり

Go のコンパイラも実行前に機械語へ変換します。Go のコンパイラはコンパイルの速さを重視しており、一般に GCC や LLVM ほど最適化を重ねません。メモリは GC が回収するので、メモリの確保と解放が多い binary-trees で差が大きくなります。

JavaScript

JIT コンパイル・GC あり

Node.js の V8 エンジンは、最初はバイトコードを解釈して実行し、何度も実行される部分を実行中に機械語へ変換します（JIT コンパイル）。変数の型は実行するまで決まらないので、V8 は実際に来た型を記録してから機械語を作ります。

Python

インタプリタ・GC あり

CPython はソースコードをバイトコードに変換し、バイトコードを1命令ずつ解釈して実行します。整数や小数も1個ずつオブジェクトとして扱うので、足し算1回ごとに型の確認とメモリの操作が発生します。計算をループで書く問題では、最速の言語の約20〜200倍の時間がかかります。

読むときの注意

  1. Benchmarks Game は、Intel Core i5-3330（2012年発売、4コア 3.0GHz）、メモリ 15.8GiB、Ubuntu 24.04 のマシンで、2025年1〜2月に測定しています。今の PC ではどの言語も時間が短くなるので、このページは言語どうしの比を比べるために使ってください。
  2. 「経過時間」はプログラムの開始から終了までの実際の時間です。4コアを同時に使うプログラムは経過時間が短くなります。「CPU 時間」は4コアが使った時間の合計で、並列化の効果を含めずに比べたいときに選びます。
  3. Benchmarks Game は、SIMD 命令を手で書いたプログラム、unsafe を使ったプログラム、C の関数を直接呼ぶプログラムに印を付けています。「手書き最適化を除く」を選ぶと、印の付いたプログラムを除いた中で最も速いプログラムを使います。
  4. Python のプログラムは NumPy を使わず、標準ライブラリだけで書かれています（pidigits の gmpy2 と、ctypes で呼ぶ GMP・PCRE2 を除く）。NumPy のように C で書かれたライブラリに計算を任せると、Python の時間は大きく短くなります。
  5. pidigits・regex-redux・reverse-complement では、時間の大半を C で書かれた部分（多倍長整数の GMP、正規表現エンジン、バイト列の変換）が使います。このため Python と他の言語の差が小さくなります。
  6. プログラムは有志が寄稿したもので、言語ごとに最適化にかけた手間が異なります。各レーンの「ソース」のリンクから、実際に測定したプログラムを読めます。
